# Story 22.7 — Tournée du jour : les recommandations de sources passent sous les thèmes

> **Type** : Feature (tuning de classement)
> **Statut** : CODE + TEST terminés — prêt pour /go
> **Branche** : `boujonlaurin-dotcom/tournee-themes-before-source-recos` → `main`
> **Épopée** : 22 — Tournée du jour / Essentiel

---

## Contexte

Plainte PO (post-onboarding) : juste après l'onboarding, la Tournée du jour proposait **haut**
des sections dédiées à des **médias** que l'utilisateur « n'a même pas encore beaucoup
consulté ». Il veut d'abord parcourir les **thèmes qu'il a sélectionnés et validés** ; les
**recommandations de sources** doivent par défaut intervenir **plus bas**, classées par signaux
de pertinence (source custom, abonnement déclaré, source beaucoup consultée, source suivie).

### Décisions PO validées

1. **Tendance globale** (tous comptes non personnalisés), **de moins en moins marquée à mesure
   que des préférences claires émergent** ⇒ pas de cloison rigide « thèmes toujours au-dessus
   des sources », mais une **démotion douce proportionnelle à `(1 − pertinence)`** : une source
   à fort signal peut remonter.
2. Les sources recommandées **sans lien réel** (« élargissement doux ») : **jamais masquées**,
   juste reléguées **tout en bas** du bloc sources.
3. Classement des sources entre elles : **custom + abonnement déclaré > beaucoup consultée
   (affinité) > simplement suivie**.

### État des lieux (avant)

- **Backend** `TourneeSuggester.arrange()` classait sources et thèmes **au même barème**
  (`daily_score = 0.40·explicit + 0.30·measured + 0.20·quantity + 0.10·quality`) ⇒ une source
  passait devant un thème. `daily_rank` en découle (`users.py::_arrange_tournee`).
- **Mobile** `applyScoreOrder` re-classait **tous** les blocs par la qualité de leurs articles
  (`blockScore`), sections-source suggérées incluses ⇒ un média jamais consulté mais avec un
  article « chaud » remontait au-dessus d'un thème. Fuite résiduelle côté mobile.

## Plan technique & tasks

### A. Backend — démotion proportionnelle à la pertinence ✓

- [x] `scoring_config.py` : `TOURNEE_SUGGEST_SOURCE_DEMOTION = 0.30` (pénalité max, pertinence
  nulle) et `TOURNEE_SUGGEST_SOURCE_FOLLOWED_BASELINE = 0.30` (plancher de pertinence d'une
  source simplement suivie).
- [x] `tournee_suggester.py` : `_build_pool` charge `is_custom` / `has_subscription` avec les
  sources suivies (`select(UserSource.source_id, .is_custom, .has_subscription)`).
- [x] `TourneeSuggestion.relevance` (défaut `1.0` = neutre ⇒ les thèmes ne sont jamais démotés).
- [x] Helper `_source_relevance()` : `custom | abonnement → 1.0` ; sinon
  `clamp01(max(affinité, plancher))`, plancher `0.0` pour l'élargissement doux et
  `TOURNEE_SUGGEST_SOURCE_FOLLOWED_BASELINE` pour une source suivie.
- [x] `arrange()` : après le blend et **avant** la variation quotidienne,
  `daily_score -= DEMOTION * (1 − relevance)` pour les seuls candidats `kind == "source"`.
  `_build_reason` / `breakdown` inchangés (la démotion est une priorisation, pas une raison
  affichable — les libellés restent vrais).

### B. Backend — correctif d'échelle du bruit quotidien ✓ (hors plan initial)

`randomized_sort` calcule `score / (temperature × 100) + gumbel` : la fonction est calibrée pour
les scores **en points 0–100** du scoring article. Le blend de la Tournée vit sur **0–1** : passé
tel quel, `score / 10 ∈ [0, 0.1]` est **écrasé** par le bruit de Gumbel (écart-type ≈ 1.28) et
l'ordre du jour devenait un **shuffle uniforme**. Mesuré avant correctif : une source **0.50
sous** un thème tenait quand même la tête **51 %** des jours (vs 50 % pour un tirage au sort).

⇒ Sans ce correctif, la démotion A aurait été un **no-op**. Les scores sont donc projetés sur
0–100 (`_NOISE_SCALE`) avant `randomized_sort`. Après : la variation quotidienne redevient un
shuffle **léger** (les candidats à score proche permutent encore d'un jour à l'autre), et un
écart de 0.20 ne se retourne plus que ~12 % du temps. `randomization.py` n'est pas touché (ses
autres appelants passent déjà des scores en points).

### C. Mobile — rendu fidèle au `daily_rank` ✓

- [x] `flux_continu_provider.dart` : getter `_suggestedSourceKeys` (clés des sections
  `SectionKind.source` de `_suggested`).
- [x] `_freezeScoreOrder` retire ces clés de l'**ordre gelé** : `applyScoreOrder` /
  `mergeVisibleReorder` laissent les clés absentes à leur **position absolue**, donc ces sections
  gardent leur rang `daily_rank` (qui porte déjà l'attenuation backend).
- [x] La **mesure** est intacte : `blockScores` n'est pas touché ⇒ `block_score` continue
  d'alimenter `article_impression` (PR-1). Le filtre porte sur le tri, jamais sur la mesure.
- [x] Pas de partition rigide thèmes/sources dans `_orderedTourneeKeys` (cela tuerait
  l'attenuation, décision PO #1). Les sources **favorites** restent triées par score : le filtre
  ne vise que la voie « Choisie pour vous ».

### D. Pas de migration ✓

`is_custom` et `has_subscription` existent déjà sur `user_sources` (`source.py:205,214`).
`alembic heads` = 1, inchangé.

## Tests

**Backend** (`pytest tests/services/test_tournee_suggester.py` — 13 passed) :
- une source simplement suivie est classée **après** un thème suivi comparable ;
- custom / abonnement déclaré ne sont **pas** démotés et passent devant une source suivie ;
- une source à forte affinité passe devant une source suivie sans affinité ;
- l'élargissement doux atterrit **tout en bas** et n'est **jamais masqué** ;
- garde-fou d'échelle : sur 10 seeds, le thème ouvre la Tournée ≥ 8 fois (le test **échoue**
  si `_NOISE_SCALE` retombe à 1 — vérifié).

**Mobile** (`flutter test .../flux_continu_block_score_order_test.dart` — 13 passed) :
- un média suggéré à `blockScore` 300 ne remonte pas au-dessus d'un thème à 50, et
  `state.blockScores['source:…']` vaut toujours 300 (mesure préservée) ;
- les thèmes restent triés entre eux malgré le média épinglé ;
- une source **favorite** reste, elle, classée par son score (non-régression).

## Risques / pièges

- **Attenuation vs cloison** : ne pas partitionner rigidement thèmes/sources côté mobile —
  casserait la décision PO #1. L'attenuation vit dans le `daily_score` backend.
- **Score-sort & analytics** : retirer les clés du **tri**, jamais de la **mesure**, sinon
  `block_score` retombe à `null` sur `article_impression` et aveugle l'instrument.
- **Amplitude de démotion** : `TOURNEE_SUGGEST_SOURCE_DEMOTION` est surchargeable à chaud via
  `SCORING_OVERRIDES` (rollback sans redeploy).
- **Cap + plancher** : la démotion peut réduire le nombre de sources retenues sous `sub_cap` —
  attendu (les thèmes gagnent les slots), le plancher `TOURNEE_SUGGEST_FLOOR` restant comblé par
  les thèmes.
- **Ordre gelé de la journée** : un ordre figé plus tôt le même jour par la version précédente de
  l'app peut encore contenir des clés de sections-source suggérées ; il expire à la frontière
  07h30 Paris (auto-résorption en un jour).
