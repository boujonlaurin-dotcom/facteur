## Contexte

La PR #1109 expose sur `GET /api/contents/{id}/perspectives` deux blocs additifs
au contrat **gelé** :

- `consensus` : `state` (`available`/`pending`/`unavailable`), `qualifier`
  (`polarized`/`varied`/`convergent`/null, calculé backend), `agreements[]` (≤3)
  / `disagreements[]` (≤2) avec `{text, support_count, display_domains (≤2,
  personnalisés par user), plus_count}`, `cta{agreement, disagreement}`,
  `generated_at`. Clés toujours présentes, listes `[]` hors `available`.
- `display` : gates dérivés de `coverage_count` (`is_solo`, `has_cta`,
  `has_cards`, `has_ai_card`, `has_bar`) que le client applique sans re-dériver.
- `POST …/perspectives/analyze` renvoie `"throttled": true` au cap global (30/j).

Côté mobile rien ne parse ces blocs. Design figé : export Claude Design
« Reader consensus 6C export » (`ReaderPhone6C`) — CTA court en haut d'article,
section « Analyse des angles (qualificatif) » en bas, 3 états dégradés.

## Détails d'implémentation

Voir le plan complet dans la PR. Points critiques :

- `DisplayGates.hidden()` (tout false, y compris `isSolo`) sur les deux chemins
  d'erreur qui construisent `PerspectivesResponse` à la main — une erreur
  réseau ne doit JAMAIS produire `isSolo == true`.
- `DisplayGates.fromCoverageCount(int)` : fallback uniquement si bloc absent
  d'une 200 (vieux backend), même table que `compute_display_gates` (1 → solo ;
  2 → cta+cards ; 3+ → complet).
- Qualifier jamais re-dérivé côté client ; `{N}` = toujours `coverageCount`
  (invariant #1104).
- `display_domains` personnalisés par user → jamais de cache au-delà de la
  session.
- Copy : aucun em-dash, constantes assertables (cf. tableau du plan).
- Throttled : message seul dans le sheet, sans « Réessayer » ni shimmer.
