# 30.1 — Recherche universelle (sources · sujets · thèmes · articles)

> Type : **Feature** · Cible : `main` · 1 PR · **Sans migration**

## Contexte

Le bouton loupe de Flâner (2ᵉ onglet) ne répond pas aux attentes naturelles face à une
recherche. État des lieux du code (branche `main` au 2026-07-24) :

| Constat | Fichier |
|---|---|
| Le trigger est une icône 22 px **noyée dans la barre de filtres repliable** | `feed_filter_bar.dart:279` (`_SearchTrigger`) |
| La sheet n'affiche **rien pendant la frappe** (`if (!hasQuery)` garde tout le contenu) | `search_filter_sheet.dart:184` |
| La recherche ne renvoie **que des articles** — `title ILIKE %q%` | `filter_presets.py:368` (`apply_keyword_filter`) |
| Aucune recherche de **source**, **sujet** ou **thème** — alors que les 3 filtres existent déjà (`setSource` / `setTopic` / `setTheme`) | `feed_provider.dart:543-620` |
| **Zéro résultat → écran vide**. `EmptyFilterState` existe mais n'est **jamais monté** (code mort) | `empty_filter_state.dart` |
| `CompactSearchChip` est également du **code mort** (aucune référence) | `compact_search_chip.dart` |
| `includeUnfollowed` n'est activé **que** depuis une chip « sujet du moment » — l'utilisateur ne peut pas élargir sa recherche lui-même | `feed_filter_bar.dart:114` |
| **Aucun événement analytics** sur la recherche (ni ouverture, ni soumission, ni abandon) | `analytics_service.dart` |

Conséquence : l'utilisateur qui tape « Mediapart » ou « Le Monde » (intention **source**),
ou « Écologie » (intention **thème**), obtient au mieux une liste d'articles dont le titre
contient le mot, au pire un écran blanc — sans aucune porte de sortie.

## Objectif

Transformer la loupe en **point d'entrée unique de navigation** : trouver une source, un
sujet, un thème ou un article, et — quand ce qu'on cherche n'existe pas encore dans le
compte — enchaîner sans friction sur l'**ajout de source**.

## Non-goals

- Pas de recherche plein-texte backend (corps d'article, résumé) — on reste sur le titre.
- Pas de recherche dans les articles sauvegardés (Saved a sa propre recherche).
- Pas de migration Alembic, pas de nouvel endpoint backend obligatoire (voir Lot 5).

## Plan technique

### Lot 1 — La sheet devient une recherche multi-entités (le cœur)

Réécriture de `SearchFilterSheet` (`apps/mobile/lib/features/feed/widgets/search_filter_sheet.dart`).

**Query vide** (inchangé, + 1 ajout) : recherches récentes · sujets du moment · **+ nouveau**
bloc « Tes sources » (4 sources suivies les plus récentes) en accès direct.

**Query non vide** (nouveau — aujourd'hui c'est le vide total) : résultats live, **calculés
en local, sans réseau**, avec debounce 180 ms, regroupés par section (max 3 items + « voir
tout ») :

1. **`Articles`** — ligne toujours en tête : `🔍 Rechercher « q » dans les articles`
   → comportement actuel (`setKeyword(q)`).
2. **`Tes sources`** — match sur `userSourcesProvider` filtré `(isTrusted || isCustom) && !isMuted`
   → tap = `setSource(id)` (filtre déjà existant).
3. **`Sujets suivis`** — match sur `customTopicsProvider` (nom + `canonicalName`)
   → tap = `setTopic(slugParent)` ou `setEntity(canonicalName)` selon `entityType`,
   même dispatch que `interest_filter_sheet.dart:290-310`.
4. **`Thèmes`** — match sur `macroThemeOrder` / `macroThemeToApiSlug` (`config/topic_labels.dart`)
   → tap = `setTheme(slug)`.
5. **`Ajouter une source`** — voir Lot 2.

Matching : normalisation minuscule + suppression des accents, `startsWith` prioritaire puis
`contains`, tri par (préfixe, longueur du libellé). Un helper pur testable
`search_matcher.dart` (`rankMatches<T>`) isolé du widget → tests unitaires directs.

**Ordre des sections adaptatif** : si un match **exact** existe sur une source ou un thème,
cette section passe devant « Articles » (taper « Mediapart » = intention source, pas
intention mot-clé).

### Lot 2 — Le pont vers l'ajout de source (demande n° 2)

Section `Ajouter une source`, affichée dès que la query est non vide :

- **Cas A — source du catalogue non suivie** (présente dans `userSourcesProvider` mais
  `!isTrusted && !isCustom`, ou `isMuted`) : carte « *Le Monde* — pas encore dans tes sources »
  + bouton **Ajouter**. Tap = `trustSource(id)` inline (`sources_repository.dart`) →
  `invalidate(userSourcesProvider)` → puis `setSource(id)` : l'utilisateur voit son flux
  immédiatement. Aucune navigation.
- **Cas B — rien dans le catalogue** : CTA « Chercher **« q »** sur le web et l'ajouter »
  → `context.pushNamed(RouteNames.addSource, extra: SourceAddArgs(initialQuery: q))`.
  Nécessite :
  - `SourceAddPanel` : nouveau paramètre `initialQuery` (pré-remplit `_searchController`
    + déclenche `_runSearch()` au premier frame) — `source_add_panel.dart:74-105`.
  - `AddSourceScreen` : propage `initialQuery`.
  - `routes.dart:643-648` : lecture de `state.extra`.
  L'utilisateur arrive donc sur la recherche intelligente **déjà lancée** — c'est
  l'« automatisation » demandée, sans re-saisie.

**Détection d'intention « source »** : la section passe **en tête** si la query ressemble à
une source — contient un point/`http` (domaine collé), ou match ≥ 0.8 sur un nom de source
catalogue, ou zéro match sujet/thème.

### Lot 3 — L'état vide de Flâner (le trou actuel)

Aujourd'hui : `_buildFeedList` renvoie une `SliverList` vide → écran blanc.

- Montage de `EmptyFilterState` (code mort ressuscité) dans `flaner_screen.dart:322` quand
  `state.items.isEmpty && !state.isLoading` **et** qu'un filtre est actif.
- Nouvelle variante `isKeyword` avec CTAs empilés :
  1. **Élargir aux sources non suivies** → `setKeyword(q, includeUnfollowed: true)` (Lot 4)
  2. **Chercher une source « q »** → pont Lot 2 cas B
  3. **Suivre « q » comme sujet** → `followTopic(q)` (réutilise `FollowKeywordSuggestionCard._handleFollow`)
  4. **Effacer la recherche**
- Le même écran vide sert aux filtres source/thème/sujet (CTAs 1 et 4 seulement).

### Lot 4 — Élargir la recherche (anticipation)

`includeUnfollowed` n'est aujourd'hui atteignable que via une chip « sujet du moment ».
On l'expose :

- Bandeau discret sous la barre de filtres quand une recherche mot-clé est active et que
  `state.items.length < 5` : « Seulement N résultats dans tes sources — **élargir à toutes
  les sources** ». Tap = `setKeyword(q, includeUnfollowed: true)`.
- Quand `_includeUnfollowed` est actif, la pill de recherche affiche un suffixe « · toutes
  sources » pour que l'état soit lisible.

### Lot 5 — Découvrabilité du bouton (demande n° 3)

**Décision PO (2026-07-24) : option A — header partagé.**

- **Nouvelle entrée dans le header partagé** `_SharedTopHeader` (`main_shell.dart:134`) :
  une loupe 24 px à **gauche de l'avatar profil**, donc **présente sur les deux onglets**
  et **hors de la zone filtre** de Flâner.
- Depuis L'Essentiel (onglet 1), valider une recherche **bascule sur Flâner**
  (`context.go(RoutePaths.flaner)`) avec le filtre déjà appliqué — le filtre est porté par
  `feedProvider`, partagé entre les deux onglets.
- **Le trigger de la barre de filtres reste** — mais uniquement dans son rôle d'affichage
  d'état : pill « 🔍 q ✕ » quand une recherche est active, `SizedBox.shrink()` sinon
  (aujourd'hui il occupe 34 px en permanence). On évite ainsi deux loupes côte à côte.
- Suppression du code mort `compact_search_chip.dart`.

### Lot 6 — Instrumentation

Nouveaux événements dans `analytics_service.dart` (PostHog) :

| Événement | Propriétés |
|---|---|
| `search_opened` | `origin` (`header` / `filter_bar`), `tab` |
| `search_result_selected` | `result_type` (`article`/`source`/`topic`/`theme`/`add_source`), `rank`, `query_length` |
| `search_submitted_empty` | `query_length` — recherche mot-clé rendant 0 article |
| `search_add_source_bridged` | `case` (`catalog_follow` / `smart_search`) |
| `search_broadened` | — (tap « élargir à toutes les sources ») |

Objectif mesurable : taux de recherches se terminant sur une action (vs abandon).
