# 30.1 — Recherche universelle (sources · sujets · thèmes · articles)

> Type : **Feature** · Cible : `main` · 1 PR · **Sans migration**

## Contexte

Le bouton loupe de Flâner (2ᵉ onglet) ne répond pas aux attentes naturelles face à une
recherche. État des lieux du code (branche `main` au 2026-07-24) :

| Constat | Fichier |
|---|---|
| Le trigger est une icône 22 px **noyée dans la barre de filtres repliable** | `feed_filter_bar.dart:279` (`_SearchTrigger`) |
| La sheet n'affiche **rien pendant la frappe** (`if (!hasQuery)` garde tout le contenu) | `search_filter_sheet.dart:184` |
| La recherche ne renvoie **que des articles** — `title ILIKE %q%` | `filter_presets.py:368` (`apply_keyword_filter`) |
| Aucune recherche de **source**, **sujet** ou **thème** — alors que les 3 filtres existent déjà (`setSource` / `setTopic` / `setTheme`) | `feed_provider.dart:543-620` |
| **Zéro résultat → écran vide**. `EmptyFilterState` existe mais n'est **jamais monté** (code mort) | `empty_filter_state.dart` |
| `CompactSearchChip` est également du **code mort** (aucune référence) | `compact_search_chip.dart` |
| `includeUnfollowed` n'est activé **que** depuis une chip « sujet du moment » — l'utilisateur ne peut pas élargir sa recherche lui-même | `feed_filter_bar.dart:114` |
| **Aucun événement analytics** sur la recherche (ni ouverture, ni soumission, ni abandon) | `analytics_service.dart` |

Conséquence : l'utilisateur qui tape « Mediapart » ou « Le Monde » (intention **source**),
ou « Écologie » (intention **thème**), obtient au mieux une liste d'articles dont le titre
contient le mot, au pire un écran blanc — sans aucune porte de sortie.

## Objectif

Transformer la loupe en **point d'entrée unique de navigation** : trouver une source, un
sujet, un thème ou un article, et — quand ce qu'on cherche n'existe pas encore dans le
compte — enchaîner sans friction sur l'**ajout de source**.

## Non-goals

- Pas de recherche plein-texte backend (corps d'article, résumé) — on reste sur le titre.
- Pas de recherche dans les articles sauvegardés (Saved a sa propre recherche).
- Pas de migration Alembic, pas de nouvel endpoint backend obligatoire (voir Lot 5).

## Plan technique

### Lot 1 — La sheet devient une recherche multi-entités (le cœur)

Réécriture de `SearchFilterSheet` (`apps/mobile/lib/features/feed/widgets/search_filter_sheet.dart`).

**Query vide** (inchangé, + 1 ajout) : recherches récentes · sujets du moment · **+ nouveau**
bloc « Tes sources » (4 sources suivies les plus récentes) en accès direct.

**Query non vide** (nouveau — aujourd'hui c'est le vide total) : résultats live, **calculés
en local, sans réseau**, avec debounce 180 ms, regroupés par section (max 3 items + « voir
tout ») :

1. **`Articles`** — ligne toujours en tête : `🔍 Rechercher « q » dans les articles`
   → comportement actuel (`setKeyword(q)`).
2. **`Tes sources`** — match sur `userSourcesProvider` filtré `(isTrusted || isCustom) && !isMuted`
   → tap = `setSource(id)` (filtre déjà existant).
3. **`Sujets suivis`** — match sur `customTopicsProvider` (nom + `canonicalName`)
   → tap = `setTopic(slugParent)` ou `setEntity(canonicalName)` selon `entityType`,
   même dispatch que `interest_filter_sheet.dart:290-310`.
4. **`Thèmes`** — match sur `macroThemeOrder` / `macroThemeToApiSlug` (`config/topic_labels.dart`)
   → tap = `setTheme(slug)`.
5. **`Ajouter une source`** — voir Lot 2.

Matching : normalisation minuscule + suppression des accents, `startsWith` prioritaire puis
`contains`, tri par (préfixe, longueur du libellé). Un helper pur testable
`search_matcher.dart` (`rankMatches<T>`) isolé du widget → tests unitaires directs.

**Ordre des sections adaptatif** : si un match **exact** existe sur une source ou un thème,
cette section passe devant « Articles » (taper « Mediapart » = intention source, pas
intention mot-clé).

### Lot 2 — Le pont vers l'ajout de source (demande n° 2)

Section `Ajouter une source`, affichée dès que la query est non vide :

- **Cas A — source du catalogue non suivie** (présente dans `userSourcesProvider` mais
  `!isTrusted && !isCustom`, ou `isMuted`) : carte « *Le Monde* — pas encore dans tes sources »
  + bouton **Ajouter**. Tap = `trustSource(id)` inline (`sources_repository.dart`) →
  `invalidate(userSourcesProvider)` → puis `setSource(id)` : l'utilisateur voit son flux
  immédiatement. Aucune navigation.
- **Cas B — rien dans le catalogue** : CTA « Chercher **« q »** sur le web et l'ajouter »
  → `context.pushNamed(RouteNames.addSource, extra: SourceAddArgs(initialQuery: q))`.
  Nécessite :
  - `SourceAddPanel` : nouveau paramètre `initialQuery` (pré-remplit `_searchController`
    + déclenche `_runSearch()` au premier frame) — `source_add_panel.dart:74-105`.
  - `AddSourceScreen` : propage `initialQuery`.
  - `routes.dart:643-648` : lecture de `state.extra`.
  L'utilisateur arrive donc sur la recherche intelligente **déjà lancée** — c'est
  l'« automatisation » demandée, sans re-saisie.

**Détection d'intention « source »** : la section passe **en tête** si la query ressemble à
une source — contient un point/`http` (domaine collé), ou match ≥ 0.8 sur un nom de source
catalogue, ou zéro match sujet/thème.

### Lot 3 — L'état vide de Flâner (le trou actuel)

Aujourd'hui : `_buildFeedList` renvoie une `SliverList` vide → écran blanc.

- Montage de `EmptyFilterState` (code mort ressuscité) dans `flaner_screen.dart:322` quand

## Réalisé

### Écarts assumés par rapport au plan

- **Cold start** : le plan prévoyait « 4 sources suivies les plus récentes ». Aucune date
  d'ajout n'est exposée côté modèle `Source` — remplacé par les **sources favorites**
  (`userSourcesStateProvider.favorites`, cap 6), qui portent une vraie intention utilisateur
  plutôt qu'un ordre arbitraire.
- **`includeUnfollowed` déplacé dans `FeedFilterSelection`.** Non prévu : `setKeyword(q,
  includeUnfollowed: true)` avec le même mot-clé ne changeait pas la sélection, donc l'UI ne
  se redessinait pas (`FeedFilterSelection.==` ignorait le périmètre). Le drapeau fait
  maintenant partie de la sélection, et `_restoreFiltersFromSelection` le restaure au lieu
  de le remettre à `false` — ce qui rétrécissait silencieusement une recherche élargie après
  un rebuild du notifier.
- **`FollowKeywordSuggestionCard` masquée quand la liste est vide** : l'état vide porte déjà
  « suivre ce sujet » parmi ses rattrapages, deux invitations empilées faisaient doublon.
- **`search_submitted_empty` dédupliqué** par signature `mot-clé|périmètre` : l'état vide est
  reconstruit à chaque rebuild du sliver, l'événement serait parti en boucle au scroll.

### Passe SIMPLIFY (4 revues parallèles : réutilisation · simplification · efficacité · altitude)

**Appliqué**

- **Perf de la sheet.** `build()` dépend de `MediaQuery` (insets clavier) : il rejouait à
  chaque frame de l'animation d'ouverture du clavier, relançant un balayage complet du
  catalogue. Sections désormais **mémoïsées** sur `(query, identité des listes source/sujet)`.
- **Matcher.** La requête n'est plus repliée une fois par candidat (≈600 `StringBuffer`
  identiques par frappe) mais une fois par passe ; le découpage par `RegExp.split` est
  remplacé par un balayage `indexOf` unique ; le tri est décoré (plus de `label()` ni de
  `toLowerCase()` dans le comparateur).
  *Changement de sémantique assumé et testé* : une requête contenant elle-même un séparateur
  (« monde diplo », « lemonde.fr ») était condamnée à `contains` par le découpage en mots ;
  elle remonte maintenant en `wordPrefix`, ce qui est le classement juste.
- **Paramètre `limit` de `rankMatches` supprimé** : aucun appelant de production, le cap vit
  dans `SearchSection` qui a besoin du total non borné.
- **`FeedNotifier.clearFilters()`** : la liste des dimensions de filtrage vivait en 3 copies
  (c'est l'oubli de `setSource(null)` dans `feed_filter_bar.dart` qui l'avait déjà montré).
- **`FeedFilterSelection.activeKind`** : `EmptyFilterState` prend un `FeedFilterKind` au lieu
  de 4 booléens (16 états encodables, 5 valides) ; `_hasAnyFilter` disparaît de l'écran.
- **Analytics hors du build.** `search_submitted_empty` passe par un `ref.listen` sur la
  transition d'état — le garde-fou de déduplication par signature devient inutile.
- **Navigation rendue au hôte.** La sheet n'introspecte plus le routeur et ne fait plus de
  `go()` : elle applique le filtre et rappelle `onApplied`. C'est `HeaderSearchButton` qui
  bascule sur Flâner quand il est monté sur L'Essentiel.
- **`HeaderSearchButton` sort du shell** vers `features/feed/widgets/` — même découpage que
  `ProfileAvatarButton`. Le shell ne compose plus que la mise en page.
- **Sortie manquante corrigée** (trouvée par la revue altitude) : L'Essentiel ne monte jamais
  la barre de filtres, donc la loupe du header y signalait une recherche active **sans aucun
  moyen de l'effacer**. La sheet porte désormais un « Effacer la recherche » quand elle est
  ouverte sur une recherche en cours.
- **Duplications retirées** : `foldForSearch` remplace `_fold` dans `grille_result_view.dart` ;
  `followKeywordAsTopic` est partagé avec `FollowKeywordSuggestionCard` ; `isFollowedSource`
  remplace les deux copies inline du prédicat ; `openAddSourceFor` centralise le pont
  analytics + route.

**Écarté** (noté, hors périmètre du diff)

- Rendre `_SectionHeader` public et refactorer les 4 en-têtes inline de `source_filter_sheet`
  / `interest_filter_sheet` : touche le rendu de deux sheets non couvertes par cette PR.
- Fusionner `_SourcePill` et `_FavoriteChip` : la revue elle-même relève un écart de bordure
  (donc un changement de pixels dans deux autres sheets).
- Mutualiser un `favoriteSourcesProvider` avec `source_filter_sheet`.
- Retirer le debounce de 180 ms : signalé comme arbitrage, pas comme gain net. Conservé —
  avec la mémoïsation, il évite quand même un balayage par frappe rapide.

### Ronde de fix post-review (2026-07-25)

La review de la PR #1006 a confirmé 0 régression mais relevé 6 défauts, corrigés ici.

- **F1 — « Effacer la recherche » téléportait vers Flâner.** `_clearSearch` appelait
  `onApplied`, qui depuis L'Essentiel navigue vers Flâner : annuler une recherche changeait
  d'onglet. `onApplied` n'est plus appelé sur l'annulation (le test qui figeait l'ancien
  comportement est corrigé en même temps).
- **F2 — le compteur de section est devenu « voir tout ».** Il affichait un nombre nu non
  tappable : 12 sources matchantes = 3 lignes et 9 inaccessibles. `SearchSection` porte
  désormais `allResults` (non cappé) en plus de `results`, et la sheet déplie/replie la
  section (`_expandedSections`, purgé à chaque changement de requête). Corollaire : la
  section « Ajouter une source » ne compte plus la recherche intelligente comme un match
  tronqué (`hasMore` était vrai à tort dès 2 catalogues).
- **F3 — `search_submitted_empty` en doublon, et perdu au premier coup.** La dédup retirée
  en SIMPLIFY est réintroduite dans une classe pure testable
  (`utils/empty_search_reporter.dart`), et l'état **courant** du provider est inspecté au
  montage — sans quoi une recherche bredouille lancée depuis L'Essentiel n'était jamais
  remontée (l'écran n'est pas encore monté quand le refresh se termine).
- **F4 — `query_length` et `rank` inexploitables.** `query_length` lisait le champ de saisie,
  vide sur tout le cold start (recherche récente, source favorite, sujet du moment) → il vaut
  désormais le libellé réellement choisi. `rank` est **global** au lieu de repartir à 0 à
  chaque section.
- **F5 — état vide au-dessus d'un bloc Explorer plein.** Sur un filtre thème/sujet, « Aucun
  article » s'affichait en pleine page alors que des articles chargeaient juste en dessous.
  `EmptyFilterState` gagne une variante `compact` (bandeau, sans CTA de sortie), utilisée
  quand des slivers Explorer suivent.
- **F6 — micro-fixes.** `_onQueryChanged` teste `_query.trim().isEmpty` (une espace initiale
  cassait le chemin instantané) ; `hasExact` balaie toute la liste au lieu du seul premier
  match ; l'état vide résout un **libellé lisible** pour les filtres source/thème/sujet
  (jamais un slug brut — `null` et titre générique si non résolvable).

**Reporté en suivi** (hors périmètre de cette PR) : couverture E2E Playwright du parcours
« source absente → écran d'ajout pré-rempli » ; `search_add_source_bridged` cas
`smart_search` documenté mais jamais émis par `_openAddSource`.

Dernier passage PO avant mise en prod. Trois demandes, une seule conséquence : la barre
de filtres n'a plus qu'un rôle, naviguer entre ses onglets épinglés.

- **Engrenage « gérer » sticky.** L'affordance d'ajout/gestion des onglets vivait comme
  dernier item du `ListView` horizontal : elle sortait de l'écran dès qu'on avait quelques
  favoris, c'est-à-dire exactement quand on en a besoin. `FavoriteTopicTabs` rend désormais
  un `Row` : `Expanded(ListView des onglets)` · `trailing` · séparateur · pill « gérer ».

  double emploi avec la recherche universelle, qui couvre déjà source · sujet · thème ·
  mot-clé depuis un point d'entrée plus lisible. `FeedFilterBar` redevient un
  `ConsumerWidget` sans état local.
- **Loupe du header en état « actif ».** Une recherche en cours transforme la loupe en pill

  que F1 ci-dessus). La pill « 🔍 mot-clé ✕ » de la barre Flâner reste : c'est elle qui

Tests : `favorite_topic_tabs_test.dart` (engrenage et `trailing` hors `Scrollable`, plus
aucun entonnoir) et le nouveau `header_search_button_test.dart` (repos / actif / ✕ efface
sans ouvrir la sheet / loupe ouvre la sheet).

### Ajustements pré-merge — PO (2026-07-25)

Quatre points bloquaient la merge côté PO. Traités en une passe (mobile + backend).

- **1 — Loupe unifiée (tous les filtres).** La loupe ne regardait que `keyword` ; or les
  setters du notifier sont exclusifs, donc choisir une **source**/**sujet**/**thème** mettait
  `keyword` à `null` → la loupe repassait en icône neutre alors qu'un filtre était bien actif
  (et sans affordance si la source n'était pas épinglée). Nouveau provider dérivé
  `activeFilterLabelProvider` (`providers/active_filter_label_provider.dart`) : source de
  vérité unique qui résout le libellé de **n'importe quelle** dimension (fallback slug/id).
  Le header (`header_search_button.dart`) et la pill de la barre (`feed_filter_bar.dart`) le
  consomment — plus de libellés divergents. Le ✕ appelle `clearFilters()` (un geste efface
  tout). Bascule icône ↔ pill animée (`AnimatedSize` + `AnimatedSwitcher`, 200 ms). Le CTA
  « Effacer la recherche » de la sheet devient « Effacer le filtre », gaté sur *toute*
  dimension active.
- **2 — Transition Essentiel → Flâner contextualisée.** `_applyAndClose` réordonné
  `pop → onApplied → await apply` : la bascule d'onglet part **avant** le refresh réseau
  (Flâner montre son skeleton pendant le fetch au lieu de figer L'Essentiel). Un signal
  éphémère (`providers/search_navigation_provider.dart`, armé par le header avant `go(flaner)`)
  fait afficher un bandeau contextuel ~3 s en tête de Flâner (« Résultats pour « … » » /
  « Filtré sur … ») — jamais quand le filtre change depuis la barre de Flâner (l'utilisateur
  y est déjà). Ordre analytics inchangé.
- **3a — Backend : frontière de mot + description.** `apply_keyword_filter`
  (`filter_presets.py`) passe de `ILIKE '%kw%'` (« belle » ramenait « poubelle », « Isabelle »)
  à une regex POSIX `~*` en **début de mot** : chaque token → `\m` + `re.escape(token)`, AND
  entre tokens, sur `title` **OU** `description`. SQL généré :
  `(title ~* '\mbelle' OR description ~* '\mbelle') AND (title ~* '\mepoque' OR description ~* '\mepoque')`.
  Pas de `\M` final (les flexions « belles »/« bellement » passent). L'entrée est échappée :
  `%`/`_`/`(` ne sont plus des jokers ni des métacaractères.
  **Perf** : pas d'index trigram sur `contents.title`/`description` → c'est un seq scan sur la
  fenêtre de candidats, comme avant. Le choix `title OR description` est **déjà** le pattern
  de prod dans `veille/feed_filter.py` (mêmes colonnes non indexées, même `~*`) — pas de charge
  nouvelle, pas de migration, pas d'extension. Repli sur `title` seul possible si une mesure
  prod montrait une dégradation. Note hors scope : pas de dépliage d'accents côté serveur
  (comportement inchangé — « époque » ≠ « epoque » en SQL).
- **3b — Mobile : frontière de mot + fuzzy.** `search_matcher.dart` : tier `contains` (celui
  qui produisait « Isabelle » pour « belle ») **retiré** — ne restent que
  `exact` > `prefix` > `wordPrefix`, plus un nouveau tier `fuzzy` (Levenshtein bornée : ≤1 pour
  4-6 caractères, ≤2 à partir de 7, jamais sous 4 ; comparé mot à mot du candidat, sur label +
  alias). Rattrape « lemonde » → « Le Monde », « libertaion » → « Libération ». Implémentation
  itérative deux lignes avec early-exit. Pas de fuzzy sur les articles (décision PO — backend
  strict).
