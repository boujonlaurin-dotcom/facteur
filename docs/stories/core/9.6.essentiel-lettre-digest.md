# Story 9.6 — Refonte « Ton Essentiel » : digest rédigé à références inline

## Statut
PR1 (backend) en cours — plan validé par le PO (Laurin), GO donné le 2026-07-13.

## Contexte

La carte « Ton Essentiel » affiche 5 articles empilés (`EssentielHiFiCard`). La refonte
(maquettes 3a « lettre liée » + 3b « rubriques », 3c exclue) remplace les 5 articles par
un **digest rédigé concis où les références SONT la navigation** :

- Chapô fluide 2-4 phrases (1-2 sujets forts, boutons source inline).
- 2-3 lignes-rubriques (pill thème ↘ en tête + 1 phrase avec bouton(s) source ↗).
- Pied « autres thèmes » (pills ↘).
- Bouton **source** = sobre, logo + nom + ↗, ouvre l'article dans le reader.
- Bouton **thème** = pill colorée + ↘, scrolle vers la section de la Tournée.
- Voix éditoriale neutre : jamais de « je », jamais d'em-dash.
- Chaque article des picks référencé exactement une fois.

## Architecture (décisions clés)

| Sujet | Décision |
|---|---|
| Format LLM | Plan déterministe serveur (`build_letter_plan`) ; le LLM ne rédige que la prose avec marqueurs `[[n]]` (n = rang du pick). Validation serveur = comptage. |
| Stockage | Nouvelle table `essentiel_letters` (RLS lockdown pattern sec02). Migration additive, 1 head. |
| Snapshot | La lettre stocke SON snapshot des 5 picks ; seuls is_read/is_saved sont réhydratés au serve. Lettre figée pour la journée. |
| Modèle LLM | `mistral-small-latest`, temp 0.35, max_tokens 700 via `EditorialLLMClient.chat_json(call_site="essentiel_letter")`. |
| Rollout | Pas de feature flag : `EssentielResponse.letter` nullable. `letter == null` → mobile rend la carte actuelle. |
| Génération | Job nocturne 08h00 Paris (après digest cron 07h30) + on-demand 8s en secours dans le router. Serein = variante on-demand cachée `(user, date, true)`. |
| Nav thème | Pill thème → `pendingFeedSectionKeyProvider = 'theme:<slug>'` (mécanisme existant). |
