# Story 33.5 — Espacer les répétitions du carrousel injecté dans la pile Essentiel

**Type** : Feature
**Statut** : Code + tests faits, PR ouverte
**Branche** : `boujonlaurin-dotcom/essentiel-carrousel-cooldown`

## Contexte (pourquoi)

Le carrousel Phase B du jour (`saved` / `quiet_sources` / `community` / `new_source`,
Story 32.1) est injecté dans la pile swipeable de l'Essentiel
(`essentiel_deck.dart::essentielTriagePool`, items du carrousel non déjà dans le slate).
Chaque builder (`carousel_catalog.py`) est **déterministe** : `build_saved` reprend
toujours le top-N par `saved_at desc`, `build_quiet_sources` le dernier article par
source discrète, `build_community` le top-N par score decay. Si l'utilisateur n'agit
pas sur ces articles (garde/passe), et que la rotation date-seedée retombe sur le même
type à quelques jours d'intervalle (probable avec 4 types en rotation), le **même**
article revient dans la pile à quelques jours d'écart → sensation de répétition/statique
signalée par Django.

Objectif : espacer d'au moins **7 jours** la réapparition d'un même article via ce
mécanisme, en repli sur le type de carrousel suivant de la rotation si le type du jour
est entièrement en cooldown.

## Décisions produit (validées avec Django, 2026-08-19)

- **Cooldown** : 7 jours (`ESSENTIEL_CAROUSEL_REPEAT_COOLDOWN_DAYS`), constante isolée
  et facilement ajustable.
- **Fallback** : si tous les candidats d'un type sont en cooldown, on saute au type
  suivant de la rotation (jamais de repeat forcé) ; si tous les types le sont, pas de
  carrousel ce jour-là (= comportement fail-open déjà existant, aucun changement).
- **Portée** : les 3 types cités par Django (`saved`, `quiet_sources`, `community`) +
  `new_source` par cohérence (même boucle de sélection, coût nul à inclure).
- **Surface** : Essentiel **uniquement**. Flâner (`build_phase_b`, carrousels affichés
  hors carte Essentiel) n'est **pas** concerné — les builders `carousel_catalog.py`
  sont explicitement documentés "surface-indépendants" (exclusion `consumed_ids`
  seulement, partagés Flâner ↔ Essentiel) ; y ajouter le filtre cooldown romprait cette
  invariance et réduirait le pool Flâner sans qu'on nous l'ait demandé. Le filtre est
  donc appliqué **après coup**, uniquement dans `select_essentiel_carousel` (le seul
  point d'entrée Essentiel), jamais dans les builders ni dans `build_phase_b`.

## Implémentation

### 1. Schéma — migration additive (1 colonne, 0 backfill)

`UserContentStatus.essentiel_last_shown_at: datetime | None` (`TIMESTAMPTZ`, nullable).
Migration `es01_essentiel_carousel_last_shown.py`, `down_revision =
"su03_support_link_delivery"` (head actuel), `op.execute("ALTER TABLE
user_content_status ADD COLUMN IF NOT EXISTS essentiel_last_shown_at TIMESTAMPTZ")`
(idempotent, patron `rd01_ucs_completed_at.py`). `NULL` = jamais montré via ce
mécanisme = éligible immédiatement. Downgrade : `DROP COLUMN IF EXISTS` symétrique.
Ajout du `mapped_column` correspondant dans `app/models/content.py` (après
`completion_source`, ligne ~204).

### 2. Filtrage cooldown — `carousel_selection_service.select_essentiel_carousel`

Avant la boucle de rotation, une requête charge
`{content_id where essentiel_last_shown_at >= now - 7j}` pour `ctx.user_id`. Dans la
boucle, après `spec.build(ctx)`, filtrer via `content.excluding(recently_shown_ids,
MAX_CAROUSEL_ITEMS)` puis re-vérifier `len(items) >= spec.min_items` (comme le check
existant) avant de retourner — sinon `continue` vers le type suivant. `build_phase_b`
(Flâner) et les builders eux-mêmes sont **inchangés**.

### 3. Écriture du "dernier montré" — `routers/essentiel._enrich_essentiel_carousel`

Après un `select_essentiel_carousel` non-`None` **et** après le retrait des 5
articles déjà affichés dans la carte (`content.excluding(shown_ids, ...)`, l.109),
upsert `essentiel_last_shown_at = now()` pour chaque `content_id` des items
**effectivement** attachés à `response.carousel`, même patron que
`feed.py:585-607` (`on_conflict_do_update(index_elements=["user_id","content_id"],
set_={"essentiel_last_shown_at": now, "updated_at": now})`, avec des valeurs d'insert
par défaut sûres — `status: UNSEEN` — pour les lignes qui n'existent pas encore, par ex.
`quiet_sources`/`community`/`new_source` où l'utilisateur n'a pas forcément déjà une
ligne `UserContentStatus`). Fail-open : erreur d'upsert loggée, ne bloque pas la
réponse (patron déjà en place dans `_enrich_essentiel_carousel`, try/except large).
Pas de `db.commit()` explicite : `get_db` commit la session en fin de requête.

## Réutilisation (pas de nouveau code)
`CarouselContent.excluding()` ; patron upsert `on_conflict_do_update` de `feed.py` /
`content_service.py` ; patron migration additive idempotente `rd01_ucs_completed_at.py`.

## Delta de comportement connu (borné, assumé)
Un carrousel peut, certains jours, être plus fin (voire absent) qu'aujourd'hui si tous
ses candidats sont en cooldown — comportement voulu (fallback), déjà couvert par le
fail-open existant. Aucun impact sur Flâner.
